# 架构与边界

## 数据流

```text
打开面板自动布防
TRACK_CHANGED / IMPORT_MEDIA_COMPLETE / 1.2s poll
                         |
                         v
             扫描活动序列的音频 TrackItem
                         |
                         v
            ProjectItem -> getMediaFilePath()
                         |
                         v
   可信采集位置 + 默认录音名 + 非基线 + ProjectItem 去重
                         |
                         v
              文件大小/mtime 连续稳定
                         |
                         v
       从 project.path 推导并确保同级标准目录可用：
        Adobe Premiere Pro Captured and Generated
                         |
                         v
        安全随机 UUIDv4 -> 本地目标冲突检查/重试
                         |
                         v
     同盘 fs.rename；跨盘 COPYFILE_EXCL + 分块 SHA-256 核验
                         |
                         v
     changeMediaFilePath -> refreshMedia -> isOffline/path 验证
                         |
                         v
 ProjectItem + 当前序列全部 TrackItem createSetNameAction
                         |
                         v
 跨盘再次核验上下文/目标/源 -> 源改到隔离名 -> 核验后删除
                         |
                         v
                 写 schema 4 轻量 sidecar
```

## 模块

- `src/core.js`：纯命名、解析、跨平台路径判断和工程同级 `Adobe Premiere Pro Captured and Generated` 目录推导。
- `src/state.js`：状态 schema、设置迁移、最近历史提交和历史上限；不承担录音 ID 计数。
- `src/panel-state.js`：纯函数形式的准备状态、主操作和四步处理链派生逻辑。
- `src/folder-readiness.js`：通过 UXP `fs.lstat()` 检查备用采集源，通过 `fs.mkdir()` 创建并验证固定最终目录，并生成中文恢复提示。
- `src/media-candidates.js`：按媒体路径和 ProjectItem ID 去重；同一素材多轨复用只保留一个候选并聚合其全部 TrackItem。
- `src/sha256.js`：固定内存、分块更新的纯 JavaScript SHA-256，用于跨盘源文件与目标副本内容核验。
- `src/transaction.js`：可注入依赖的同盘移动、跨盘排他复制与安全清理、重链接、ProjectItem/TrackItem 名称同步、逐项验证和文件事务回滚。
- `src/coordination.js`：自动扫描、手动批处理和设置写入共用的串行队列，监听/面板生命周期代次令牌，以及导入完成状态过滤。
- `src/main.js`：UXP/Premiere 适配、面板状态、事件、轮询、候选识别和批量处理。
- `plugin/`：manifest、面板 HTML/CSS 和图标。
- `dist/`：`npm run build` 生成的 UXP 侧载目录。

## 决策

- 以轮询为可靠主路径。Adobe 没有公开 `VOICEOVER_RECORD_FINISHED` 事件；`IMPORT_MEDIA_COMPLETE` 只有状态，没有新 ProjectItem ID。
- 打开面板后，已保存工程且存在活动序列时自动建立监听；用户只点击时间线原生“画外音录制”麦克风，不需要选择目录或点击“开始监听”。面板隐藏或销毁时停止监听，重新打开后重新建立上下文和基线。
- 自动候选必须同时满足可信采集位置和 Premiere 默认录音名：中文 `音频 N.wav` / `音频 N_N.wav`，或英文 `Audio N.wav` / `Audio N_N.wav`。普通 `music.wav`、自定义录音名和旧录音不会走自动改名；它们通过带预览的“扫描遗漏”进入人工确认流程。
- 录音停止后不会立即改名：插件连续观察文件大小和修改时间，当前生产参数为 3 次稳定轮询和约 3000ms 静默，通常在约 3-4 秒后进入改名事务；文件仍在写入时继续等待。
- 新写入文件名为 `项目名-<32位小写十六进制录音ID>.wav`，例如 `318最终版-7f3c9a2e4b1d48f0a6c1e8d2b9f04a77.wav`；不包含音轨、序号和时间。录音 ID 是 128 位 UUIDv4（其中 122 位为随机位）去掉连字符后的表示，由 UXP 运行时安全随机源生成。
- 项目名来自 `Project.name`，移除 `.prproj` 后替换 Windows 禁用字符；项目名最多保留 80 个 Unicode 字符。
- 文件时间仍可用于扫描遗漏时的排序，但不写入新文件名，也不参与录音 ID 生成。
- 当前 UUID 格式与三类旧格式（无时间序号 `项目名-000123.wav`、项目序号加时间 `项目名-000123-yyyyMMdd-HHmmss.wav`、轨道加序号加时间 `项目名-A02-003-yyyyMMdd-HHmmss.wav`）都可被解析。旧格式仅对监听启动前的历史基线提供保护；新出现的自定义名或旧格式不会自动改名，只有扫描选中并确认后才进入 UUID 升级流程，不恢复或递增任何计数；项目名改动后，UUID 文件仍凭 UUID 格式识别。
- 生成目标名时先检查本地目标是否存在。若存在则重新生成 UUID 并重试；任何路径冲突都不得覆盖已有文件。两个离线项目副本或不同协作者不共享计数器、项目副本状态或网络服务，合并后 UUID 重合的概率极低但不是绝对数学保证；冲突检查是最后一道本地保护。
- 接手交接时以“录音身份”和“文件内容”双重核对：同一 UUID 且内容相同可去重；同一 UUID 但内容不同必须隔离冲突文件、为其中一份重新生成 UUID，并只更新对应工程的媒体路径和素材名。不能依赖资源管理器覆盖、按序号续号或只看文件名尾部。
- 监听启动后，新出现的旧序号/旧时间格式不是自动候选；它们与自定义名一样留待“扫描遗漏”预览确认。启动时已存在的历史文件仍按基线保护，避免打开旧工程时自动改写旧素材。
- 同一 ProjectItem 出现在当前序列多处时按媒体路径只处理一次，并在同一个 Premiere compound transaction 中同步全部对应 TrackItem 名称；同一路径若关联多个不同 ProjectItem，则跳过并报错，避免只重链接其中一个素材。
- 自动监听建立基线，不追溯旧素材；追溯必须通过带预览确认的“扫描遗漏”。候选从 Premiere scratch/capture 路径或备用采集源目录发现，但所有处理结果统一进入与当前已保存 `.prproj` 同级的 `Adobe Premiere Pro Captured and Generated` 文件夹。多个 `.prproj` 位于同一父目录时共用该文件夹，依靠项目前缀和 UUID 区分。
- 每条录音热路径只做发现 WAV、等待稳定、生成 ID、同盘移动或跨盘排他复制与内容核验、单个 ProjectItem 重链接，以及当前序列全部对应 TrackItem 名称同步、在线验证和轻量 sidecar 更新；完全不调用 `project.save()`，不因一条录音重写整个 `.prproj`。工程持久化交给用户的 `Ctrl+S`、Premiere 自动保存或关闭项目时的保存提示。
- 已在最终 `Adobe Premiere Pro Captured and Generated` 文件夹且使用 UUID 文件名、但时间线片段名仍停留在旧默认名的历史项，会在监听启动或序列切换后的首次扫描执行名称修复；该路径只读取并更新 Premiere 名称，不修改磁盘文件或媒体链接。位于其他目录的 UUID 录音必须经“扫描遗漏”确认后移入，并保留其 UUID。
- `0.3.3` 错误创建的工程同级 `录音` 文件夹属于历史来源。`0.3.4` 不自动移动或删除它；需要整理时先将其设为备用源，再通过“扫描遗漏”预览确认。
- 新 WAV 尚未出现在当前序列时持续保留为待关联项；60 秒后只警告一次并退避到 10 秒探测，5 分钟后退避到 30 秒。导入、音轨或序列事件可立即唤醒，不会加入永久忽略基线。
- Premiere 暂时持有 WAV 文件锁时继续退避重试，只记录黄色等待提示，不进入红色失败状态或增加异常计数；文件释放后沿原事务继续处理。
- 同盘使用 `fs.rename()` 移入最终目录。Windows 不同盘符、macOS 不同 `/Volumes/<卷名>` 或不同 UNC 共享会直接使用 `fs.copyFile(..., COPYFILE_EXCL)` 排他复制，不依赖一次失败的跨卷 rename 才判断；未知挂载点仍可从 `EXDEV` 回退复制。
- 跨盘复制返回成功后，使用 `fs.open/read/close` 以 1 MiB 分块读取并计算 SHA-256；只有源身份未变化、源与目标大小及摘要一致时才重链接。分块读取每 8 MiB 主动让出事件循环，不把整段 WAV 一次载入内存。
- 跨盘重链接和名称同步全部验证成功后，清理阶段会再次核对项目/序列、工程目录副本摘要及原始源身份；源文件先在原目录原子改到 UUID 派生的隐藏隔离名，隔离文件摘要仍一致才删除。任何不确定情况都保留可恢复文件并显示中文警告。
- 跨盘失败回滚不会自动删除工程目录目标路径中的文件，因为该路径可能已被外部进程替换；宁可保留额外副本，也不删除身份未确认的数据。删源失败不会回滚已经验证成功的最终链接。
- 同盘改名事务在磁盘移动、重链接、素材名事务和在线验证之间反复核对活动项目/序列；发生切换或文件操作失败就回滚文件名与素材内存状态。工程保存不参与该事务，因此工程保存结果不会触发热路径恢复流程。
- 手动预览记录源文件的大小、mtime、birthtime、ctime 和可用 inode；确认后身份变化会中止该条，而不是套用旧计划。
- 自动监听在文件连续稳定后也记录完整身份签名，并在事务开始前复核，避免稳定检测与改名之间源文件被替换。
- 面板销毁会使排队中或等待确认的手动批处理失效；若单条改名事务已经开始，则让该事务完成并在下一条前停止，避免留下半改名状态。
- 全局 `IMPORT_MEDIA_COMPLETE` 监听在面板销毁时使用同一事件名和回调解绑；取消或失败状态不触发加速扫描。
- 未保存工程仍保留项目上下文供准备区显示，但不允许选择目录、写 sidecar 或开始监听；保存后刷新会重新建立持久身份。
- 上下文刷新先在局部读取工程、状态文件和目录有效性，再用刷新代次只提交最后一次结果，避免较慢的旧项目读取覆盖新项目面板。
- 备用采集源目录若已配置，必须通过存在性和目录类型验证；它不是自动待命的前置条件，也不能改变最终保存位置。启动监听和轮询会优先复核该目录，失效时回退到 Premiere capture 路径识别并提示重新选择备用源。
- 事务通过只读阶段通知驱动面板中的“重命名、重链接”状态；通知失败不会影响文件事务，界面不使用模拟进度。

## 持久化边界

- sidecar schema 4 是小型设置与最近历史文件，只保存备用采集源目录、自动启动等设置及有限条最近记录；最终保存目录始终由 `project.path` 推导。录音 ID 不从 sidecar 计数，也不依赖 sidecar 才能保证命名分散性。它不等同于保存 `.prproj`。
- UUIDv4 的唯一性依赖 UXP 运行时安全随机源；若目标运行时不提供符合预期的安全随机能力，应停止启用自动命名并报告，而不是退回共享计数器或伪随机时间命名。它提供的是工程上极低碰撞概率，不是离线环境中的数学绝对保证；绝对保证需要共享登记服务或集中分配的命名空间。
- 若在下一次正常工程保存前发生 Premiere 崩溃、强制退出或断电，录音可能已经移动或复制到最终目录，但工程快照仍保存原始采集路径；重开后可能出现路径过时或离线，需要重新扫描/重链接。未来可增加恢复 journal 提高崩溃恢复能力，但不属于当前 MVP。

## 未经运行时验证的假设

- Premiere 26.0.1 的时间线原生录音会在结束后产生可从 AudioTrack TrackItem 获取的 ClipProjectItem。
- 原生录音的 TrackItem 在 WAV 文件释放前后会触发至少一次 `TRACK_CHANGED` 或被轮询发现。
- `fs.rename()` 在 Premiere 释放 WAV 句柄后可完成同卷跨目录移动；`fs.copyFile()` 的 `COPYFILE_EXCL`、数字文件描述符 `open/read/close`、`fs.unlink()`、外置卷权限和网络共享行为符合 Adobe 文档及当前实现预期。Windows、macOS 外置卷和网络共享仍须分别实机验收。
- `ClipProjectItem.createSetNameAction()` 与 `AudioClipTrackItem.createSetNameAction()` 成功后，对应名称会在短延迟后同步更新；本机 26.0.1 的真实行为仍须复测。
- 面板隐藏或销毁回调会停止监听并解绑事件；UXP 宿主是否在每个版本可靠触发隐藏回调仍需实机确认，期间产生的录音可通过“扫描遗漏”恢复。
- 多个 Premiere 实例同时写入同一最终目录时，目标创建由 `COPYFILE_EXCL` 防止覆盖，发现 `EEXIST` 后会重新生成 UUID；同盘 `rename` 的并发语义和异常回滚仍需实机验收。项目最终目录固定在各自 `.prproj` 同级，原始 Captured Audio 目录只负责采集发现。
- 工程文件改名会改变旁路状态文件名；UUID 文件不依赖工程名即可被识别，旧序号格式仍按其旧项目名前缀识别且不会二次改名。sidecar 只迁移设置和最近历史，不承担跨副本编号同步。
