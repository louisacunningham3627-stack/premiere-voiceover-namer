# 录音响应与回收开发状态

更新：2026-09-06。当前构建为 0.4.0，Windows 插件与原生回收助手合并安装。Premiere 内完整操作闭环尚待临时工程验收。

验证：`npm run check` 的 174 项测试通过，构建清单、脚本顺序及源文件哈希校验通过。原生助手 11 项验证用合成 WAV 完成 Windows 真回收测试，并在系统回收站核对来源目录、文件名和 SHA-256；不等同于真实 Premiere 录音验收。

## 已实现

- 新录音通过路径与新鲜度检查后，首次观察即预留目标名称。
- 文件锁重试复用同一个计划；只有目标真实冲突时才替换名称，并保留替换后的计划。
- 执行前使用最新源文件签名及当前项目、序列检查，不将首次观察的写入中签名当成最终签名。
- 文件占用重试不清空稳定观察次数；文件尺寸或修改时间变化仍重新计算稳定状态。
- 成功释放原始默认路径后，后续复用该路径的录音使用独立计划。
- Windows 一体安装包包含 UXP 面板和编译后的回收助手，不需要另装 Node.js 或手动启动助手。
- 助手通过当前用户的专用 URL 协议按需启动，处理一次请求后退出；无网络端口、开机自启、计划任务或常驻清理进程。
- 新录音成功命名后，在工程旁的 `<工程名>.voiceover-namer.json.recordings` 单独登记文件身份、SHA-256 与本机 HMAC 签名，不受最近 200 条历史上限影响。
- 打开工程不会清扫未使用的旧录音。仅本次监听观察到引用的签名登记录音，才会在最终引用消失后进入至少 30 秒宽限期；空闲时约每 10 秒完整检查一次，实际完成时间可能更长。
- 扫描全部序列、音视频轨和项目面板中的嵌套序列；任一读失败都停止回收，不把跳过的部分算成零引用。还有引用、移动路径或重复导入时保留文件。
- 助手先校验，再等待面板重新扫描和最终确认。真正回收后，面板校验响应和原路径不存在，再移除仍留在项目面板的对应素材项。
- `.issued` 标记阻止已提交或结果不确定的请求被重复执行；超时和失败保留证据并暂停回收，不影响正常命名。面板“刷新项目”可以重新检查，不需要重启 Premiere。

## 尚未实现或验收

- 初次稳定等待仍为 3 秒，没有声称达到停止录音即刻改名。需要可靠的宿主录音结束信号后才能安全缩短。
- 官方 UXP 不提供系统回收站接口。`FolderItem.createRemoveItemAction` 仅移除项目项；`fs.unlink` 不能代替系统回收站。
- Windows 仅支持本地固定磁盘及可确认的回收站，拒绝 UNC、网络盘、可移动卷、目录链接和挂载点。不会永久删除作为降级。
- “全部序列”限定为当前工程。无法可靠枚举其它工程对同一磁盘文件的引用；如果跨工程共用已登记录音，应先暂停自动处理，不能依赖此回收检查保护其它工程。
- macOS 原生回收尚未实现，命名功能保持；Mac 包明确提示此限制。
- 签名与本机安装身份绑定。正常升级保留身份，但不把他人机器的登记或被改写路径的交接登记直接作为回收授权；交接后新录音应由接手人的插件重新登记。
- 30 秒内的撤销会取消待回收；开始写入最终确认时进入不可撤销阶段，即使异步写入期间发生切换或关闭，也不能保证撤回。回收完成后的 Premiere 撤销不能恢复磁盘文件，须从系统回收站还原。源路径与 Shell 操作之间仍存在极短竞争窗口，不能宣称对同权限进程恶意替换有绝对防护。
- 真实 Premiere 25.6/26.x 下的录音、删除、嵌套/多机位、首次启动助手确认和连续录音性能仍待验收；API 缺失或读取失败只暂停回收。没有删除任何用户录音，测试仅回收专门生成的微小 WAV。

## 回收实现必须满足

- 仅允许持久登记、身份验证通过的本插件录音；不能用 UUID 文件名、目录位置或最近 200 条历史代替所有权登记。
- 删除时间线最终引用或项目项后进入宽限期；剪切、移动、撤销和重新引用取消待回收。
- 全项目所有序列、嵌套引用检查完整成功，才能认定没有引用；任何枚举失败必须保留文件。
- 真正进入 Windows 回收站或 macOS 垃圾桶，不降级为永久删除。
- 项目切换、源文件被替换、助手失败、权限不足和非回收站卷均停止回收并报告。
- 不迁移或清理历史录音，不影响音乐、音效和其它普通素材。
