# Premiere 运行验收清单

测试环境：Premiere Pro `26.0.1`，使用临时工程目录和可删除的 Captured Audio 源目录，不在正式项目上首测。

## 安装与发现

- [ ] 关闭 Premiere 后运行 `scripts\install-user-plugin.ps1`，将当前构建 `0.3.4` 安装到用户级 UXP External 目录，并确认构建与安装目录逐文件 SHA-256 一致。
- [x] 全新启动 Premiere 后，UXP 日志识别 `com.hechao.premiere.voiceover-namer`，并记录 `Number of plugins added from user's fallback: 1`。
- [ ] 在“窗口 > UXP 插件”中打开“赫朝录音命名器”，确认面板实际渲染且没有插件自身错误日志。
- [ ] 关闭 Premiere 后运行 `scripts\uninstall-user-plugin.ps1`，确认菜单项消失；按脚本输出的恢复命令还原后，确认菜单项重新出现。

### macOS

- [ ] 在 macOS 上运行 `npm run check` 和 `npm run package:macos`，确认 `outputs/macos/` 同时生成插件目录、zip 和 zip 的 SHA-256 清单。
- [ ] 在 macOS 上关闭 Premiere，运行 `npm run install:user:macos`；确认目标为 `~/Library/Application Support/Adobe/UXP/Plugins/External/com.hechao.premiere.voiceover-namer`，且逐文件 SHA-256 校验通过。
- [ ] 用 `TARGET_ROOT` 指向隔离临时目录完成一次安装和 `npm run uninstall:user:macos`；确认卸载只移动到 `PluginBackups`，不会删除目录。
- [ ] 启动 Premiere Pro `25.6.0+`，从“窗口 > UXP 插件”打开“赫朝录音命名器”，确认面板无自身错误日志。
- [ ] 在 macOS 临时工程中录制至少四条 WAV，确认文件名、ProjectItem 名、时间线片段名和媒体路径逐字一致且素材在线可播放。
- [ ] 将原始采集目录和 `.prproj` 分别放在两个 macOS 卷中，确认排他复制、分块 SHA-256、重链接和删源依次成功；同时验证外置卷授权失败时源文件保留。
- [ ] 在 `/Users/...`、根目录 `/` 和大小写不同的路径各验证一次；确认 POSIX 路径大小写敏感，网络共享 `//server/share` 按 UNC 规则比较。
- [ ] 在 macOS 上执行一次卸载和恢复，确认备份还原后 Premiere 能再次发现插件。

## 面板与引导

- [ ] 未打开工程时顶部显示“打开一个 Premiere 工程”，未保存工程时明确显示“先保存 Premiere 工程”，两者不混淆。
- [ ] 打开面板后，已保存工程和活动序列自动完成布防；不选择目录、不点击“开始监听”，即可回到时间线录音。
- [ ] 面板准备区只把“工程已保存”和“活动序列”作为用户动作；“最终保存位置”固定显示 `.prproj` 同级 `Adobe Premiere Pro Captured and Generated` 文件夹，“备用源”按钮只补充原始录音发现范围。
- [ ] 已保存的备用采集源目录被移动、删除或变成不可访问时，自动识别仍可回退到 Premiere capture 路径，并提示重新选择备用源；最终保存位置不变。
- [ ] 监听中顶部明确提示回 Premiere 录音，同时保留“暂停自动命名”和“扫描遗漏”。
- [ ] 新录音依次点亮发现 WAV、等待稳定、移入并命名、链接并改片段，失败时停在实际失败步骤；流程中没有保存工程步骤。
- [ ] 面板没有“处理后自动保存工程”设置，能明确提示工程保存由用户正常的 `Ctrl+S`、Premiere 自动保存或关闭项目提示完成。
- [ ] 当前录音的源文件名和目标文件名与活动记录、磁盘、ProjectItem 和时间线 TrackItem 实际结果一致。
- [ ] 面板在 `300×360`、`360×620`、`420×680` 下无横向滚动、文字遮挡或按钮溢出；鼠标滚轮和可见滚动条都能到达最底部活动记录。
- [ ] 自动待命/处理中折叠重复教程和连接详情，未保存/无序列/断开/暂停/错误时自动展开恢复信息。
- [ ] 各区块保持正常纵向文档流，不因 UXP 宿主压缩布局而发生标题、按钮、流程和活动记录重叠。

## 基本闭环

- [ ] 保存测试 `.prproj` 并打开活动序列；首次测试不选择目录、不点击开始按钮，直接使用 Premiere 原生录音。
- [ ] 保存 `.prproj` 后自动创建同级 `Adobe Premiere Pro Captured and Generated` 文件夹；无法创建或没有写入权限时不启动监听，并显示中文错误。
- [ ] 点击时间线音轨上的原生“画外音录制”麦克风，停止录音后等待约 `3-4` 秒稳定观察，确认面板出现处理阶段。
- [ ] 在 `A01`、`A02` 各录制两条 2 秒语音。
- [ ] 四个磁盘 WAV 均符合 `项目名-[0-9a-f]{32}.wav`，不含音轨、序号和时间；示例 `318最终版-7f3c9a2e4b1d48f0a6c1e8d2b9f04a77.wav`。
- [ ] 四个最终 WAV 全部位于 `<.prproj 所在目录>\Adobe Premiere Pro Captured and Generated`，原始采集位置不再保留已成功处理的旧文件。
- [ ] 四条录音生成四个不同的 32 位小写十六进制 ID；不因换音轨或切换活动序列而重新使用 ID。
- [ ] Project 面板素材名与磁盘文件名逐字一致。
- [ ] 每条时间线 TrackItem 的显示名与磁盘文件名逐字一致；同一 ProjectItem 在当前序列复用多次时，每个片段都已同步。
- [ ] `getMediaFilePath()` 指向新路径，四条素材 `isOffline() === false`。
- [ ] 时间线四条素材可播放，声音内容和录制顺序正确。
- [ ] 磁盘文件名、Premiere ProjectItem 素材名、当前序列 TrackItem 名和媒体路径逐字对应，四条时间线素材均可正常播放。
- [ ] 关闭并重开工程后仍在线、可播放、名称不回退。

## 恢复与边界

- [ ] 停止插件后录一条，再用“扫描遗漏”预览并处理成功。
- [ ] 将普通 `music.wav` 或自定义录音名放入可信采集目录并关联到当前序列，确认自动监听不改名；从“扫描遗漏”打开预览后才允许人工确认处理。
- [ ] 在“扫描遗漏”预览期间关闭/卸载面板，确认批处理取消且没有文件被改名。
- [ ] 批处理第一条正在改名时关闭面板，确认当前条完整结束、后续条目不再执行。
- [ ] 关闭并重载插件后继续录音，仍生成新的 ID，不依赖或恢复任何计数器。
- [ ] 同一秒连续结束两次录音，仍生成两个不同 ID。
- [ ] 连续录音期间不需要重启面板或 Premiere；每条录音完成后磁盘名、ProjectItem 名称和媒体路径一致。
- [ ] 预先创建一个将要生成的目标名，插件重新生成 ID 并成功处理，原有 WAV 内容、大小和路径均不变；任何冲突都不覆盖文件。
- [ ] 将同一个 ProjectItem 放到两个音轨，只改磁盘和重链接一次，两处 TrackItem 名均同步且不报多轨错误。
- [ ] 打开曾由旧版处理、且 UUID WAV 已在当前工程 `Adobe Premiere Pro Captured and Generated` 文件夹中的序列；新版首次扫描自动补齐片段名，不再次移动磁盘文件或重链接。
- [ ] 若工程旁存在 `0.3.3` 错误创建的 `录音` 文件夹，升级不会自动移动或删除它；将其设为备用源后，“扫描遗漏”可预览并确认移入标准目录。
- [ ] 将旧版 UUID WAV 放在最终目录之外；自动监听不把它误判为已整理项，“扫描遗漏”确认后移入最终目录并保留原 UUID。
- [ ] 让同一路径关联两个不同 ProjectItem，自动监听明确跳过并记录冲突；移除重复 ProjectItem 后无需重启，下一轮自动重试并完成改名、重链接。
- [ ] 在监听启动前放入三种旧格式：无时间序号 `项目名-000019.wav`、旧项目格式 `项目名-000014-yyyyMMdd-HHmmss.wav`、旧轨道格式 `项目名-A02-021-yyyyMMdd-HHmmss.wav`；自动监听不改名。另从“扫描遗漏”打开预览，确认后才可将选中的旧格式升级为 UUID。
- [ ] schema 4 sidecar 只包含备用采集源、自动启动等设置和有限条最近历史；不包含最终目录或 recording counter，也不因缺少 sidecar 而阻止生成 UUID。最终目录每次从 `project.path` 推导。
- [ ] 将项目文件改名或在 Premiere 中修改项目名后重载插件，已有 `旧项目名-<32位UUID>.wav` 仍被识别为已管理文件，不被二次改名，媒体路径保持在线。
- [ ] 切换序列时旧素材只进入基线；切换项目时旧监听停止。
- [ ] 隐藏面板或销毁面板后确认监听、计时器和事件解绑；隐藏期间产生的录音重新打开面板后可用“扫描遗漏”恢复。
- [ ] 连续刷新并快速切换项目时，较慢的旧请求不会把项目名、目录状态或序列覆盖回来。
- [ ] 删除、断开或改为只读的最终 `Adobe Premiere Pro Captured and Generated` 文件夹会阻止监听并给出中文错误；备用源失效只回退到 Premiere capture 自动识别，不改变最终目录。
- [ ] 临时让 Premiere 锁住 WAV，确认等待期间只显示黄色提示、不进入红色失败状态或增加异常计数；释放后自动完成处理。
- [ ] 临时让目标目录只读，确认错误日志和源文件保留。
- [ ] 模拟同盘移动或媒体重链接失败，确认 Premiere 回到仍存在的可用路径，sidecar 不写入成功记录。
- [ ] Windows 上把原始采集目录放在 C 盘、`.prproj` 放在另一盘；确认最终目标以 `COPYFILE_EXCL` 创建、源和目标分块 SHA-256 一致、Premiere 在线且名称同步后才删除 C 盘源文件。
- [ ] 模拟跨盘复制中断、同尺寸内容损坏、目标被外部替换或源身份变化；确认不重链接错误副本、不覆盖目标、不删除源，工程目录中的不确定副本也不会在回滚时被自动删除。
- [ ] 模拟源文件持续锁定或删除失败；确认最终素材仍链接工程目录副本，原始文件保留并出现“暂未删除”警告。
- [ ] 在跨盘源清理期间切换项目或序列；确认每轮清理都会重新校验上下文，源文件或隔离副本保留。
- [ ] 在插件清理前由外部移除源文件；确认活动记录明确说明“清理前已经不存在”，不误报为插件正常删除。
- [ ] 让新 WAV 延迟超过 60 秒才出现在当前序列，确认警告后仍能自动处理。
- [ ] 录制一条较长音频，确认写入期间不会提前改名，停止后文件稳定才处理。
- [ ] 在“扫描遗漏”预览停留期间替换源 WAV，确认该条中止且不会重链接替换后的文件。
- [ ] 自动监听确认文件稳定后、事务开始前替换源 WAV，确认该条中止且不会重链接替换后的文件。
- [ ] 静态检查生产 `main.js` 每条录音处理路径不包含 `project.save()` 调用；连续处理多条录音期间 Premiere 不因插件触发整工程保存。
- [ ] 让 Premiere 再次生成与上一条相同的默认源文件名，确认旧源路径已从监听基线释放，新 WAV 仍会得到新的唯一 ID。

## 多人交接与离线副本

- [ ] 从同一已保存工程制作两个离线副本，由两名操作者分别在无联网、无共享计数器的环境中并行录音；两边生成的规范 WAV 名称均符合 UUID 格式。
- [ ] 将两份副本的录音合并到各自工程旁的 `Adobe Premiere Pro Captured and Generated` 文件夹并重新链接工程；不同录音的 32 位 ID 无重复，项目旁 sidecar 不需要手工合并计数。
- [ ] 用旧版计数命名插件产生一条 `项目名-000001.wav` 或带时间的旧格式；新版自动监听不直接改名，使用“扫描遗漏”预览确认后再升级为 UUID，并同步媒体路径和素材名；启动前已有的历史基线不应自动改名。
- [ ] 交接合并预检：同 UUID 且内容相同只保留一份；同 UUID 且内容不同不得覆盖，必须隔离并为其中一份重新生成 UUID，再只更新对应工程引用。
- [ ] 明确记录：离线 UUID 是极低概率碰撞，不是数学绝对保证；若项目要求绝对零碰撞，必须在团队流程中启用共享登记或集中分配命名空间。
- [ ] 在测试中批量生成至少 `10000` 个 UUID 并统计完整 ID，确认无重复、均为小写十六进制 32 字符；记录 Premiere/UXP 版本和随机源实现。该结果是验收证据，不是绝对数学保证。
- [ ] 注入或安排安全随机源返回一个已存在 ID，确认插件检测本地目标后重新生成并继续处理；旧目标文件从未被覆盖，冲突重试次数和最终 ID 写入活动记录。
- [ ] 在两份副本同时写入同一最终目录的压力测试中，确认目标冲突、文件锁和复制失败都保留源文件，不损坏已存在音频；该场景需实机确认文件系统和 UXP 行为。

## 响应与连续工作

- [ ] 连续录制 `1`、`4`、`8`、`16` 条短音频，确认不需要重启面板或 Premiere，且没有录音中断或明显界面卡死。
- [ ] 分别用 10 MB、100 MB 和长录音验证跨盘分块 SHA-256；记录停止录音到完成链接的时间，确认峰值内存不会随整个 WAV 大小一次性增长，界面仍可滚动和刷新。
- [ ] 连续处理 `16` 条录音后手动执行一次 `Ctrl+S`，关闭并重开工程，确认所有媒体路径和素材名一次性持久化。
- [ ] 在包含至少 1000 个 WAV 的测试目录监听 5 分钟，确认空闲轮询不会持续遍历时间线或造成明显卡顿。
- [ ] 关闭并重新打开面板后用“扫描遗漏”恢复期间产生的录音。

## 保存边界

- [ ] 在处理多条录音后使用 Premiere 自动保存或关闭项目保存提示，确认重开工程后媒体仍在线可播放。
- [ ] 记录未正常保存前崩溃/强制退出的已知风险：录音可能已移动或复制到工程旁的 `Adobe Premiere Pro Captured and Generated` 文件夹，而工程快照仍引用原始采集路径；重开后按“扫描遗漏”或重新链接恢复，不把该场景误判为插件已自动保存。
