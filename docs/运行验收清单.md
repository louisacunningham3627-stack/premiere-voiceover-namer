# Premiere 运行验收清单

测试环境：Premiere Pro `26.0.1`，使用临时工程和临时 Captured Audio 目录，不在正式项目上首测。

## 安装与发现

- [ ] 关闭 Premiere 后运行 `scripts\install-user-plugin.ps1`，将当前构建 `0.3.0` 安装到用户级 UXP External 目录，并确认构建与安装目录逐文件 SHA-256 一致。
- [x] 全新启动 Premiere 后，UXP 日志识别 `com.hechao.premiere.voiceover-namer`，并记录 `Number of plugins added from user's fallback: 1`。
- [ ] 在 `Window > UXP Plugins` 中打开“赫朝录音命名器”，确认面板实际渲染且没有插件自身错误日志。
- [ ] 关闭 Premiere 后运行 `scripts\uninstall-user-plugin.ps1`，确认菜单项消失；按脚本输出的恢复命令还原后，确认菜单项重新出现。

## 面板与引导

- [ ] 未打开工程时顶部显示“打开一个 Premiere 工程”，未保存工程时明确显示“先保存 Premiere 工程”，两者不混淆。
- [ ] 打开面板后，已保存工程和活动序列自动完成布防；不选择目录、不点击“开始监听”，即可回到时间线录音。
- [ ] 面板准备区只把“工程已保存”和“活动序列”作为必需项；录音位置仅显示自动识别结果或作为备用目录入口。
- [ ] 已保存的备用录音目录被移动、删除或变成不可访问时，自动识别仍可回退到 Premiere capture 路径，并提示重新选择备用目录。
- [ ] 监听中顶部明确提示回 Premiere 录音，同时保留“暂停自动命名”和“扫描遗漏”。
- [ ] 新录音依次点亮发现 WAV、等待稳定、重命名、重链接，失败时停在实际失败步骤；流程中没有保存工程步骤。
- [ ] 面板没有“处理后自动保存工程”设置，能明确提示工程保存由用户正常的 `Ctrl+S`、Premiere 自动保存或关闭项目提示完成。
- [ ] 当前录音的源文件名和目标文件名与活动记录、磁盘和 ProjectItem 实际结果一致。
- [ ] 面板在 `300px`、`360px`、`420px` 宽度下无横向滚动、文字遮挡或按钮溢出。

## 基本闭环

- [ ] 保存测试 `.prproj` 并打开活动序列；首次测试不选择目录、不点击开始按钮，直接使用 Premiere 原生录音。
- [ ] 点击时间线音轨上的原生“画外音录制”麦克风，停止录音后等待约 `3-4` 秒稳定观察，确认面板出现处理阶段。
- [ ] 在 `A01`、`A02` 各录制两条 2 秒语音。
- [ ] 四个磁盘 WAV 均符合 `项目名-[0-9a-f]{32}.wav`，不含音轨、序号和时间；示例 `318最终版-7f3c9a2e4b1d48f0a6c1e8d2b9f04a77.wav`。
- [ ] 四条录音生成四个不同的 32 位小写十六进制 ID；不因换音轨或切换活动序列而重新使用 ID。
- [ ] Project 面板素材名与磁盘文件名逐字一致。
- [ ] `getMediaFilePath()` 指向新路径，四条素材 `isOffline() === false`。
- [ ] 时间线四条素材可播放，声音内容和录制顺序正确。
- [ ] 磁盘文件名、Premiere ProjectItem 素材名和媒体路径逐字对应，四条时间线素材均可正常播放。
- [ ] 关闭并重开工程后仍在线、可播放、名称不回退。

## 恢复与边界

- [ ] 停止插件后录一条，再用“扫描遗漏”预览并处理成功。
- [ ] 将普通 `music.wav` 或自定义录音名放入可信采集目录并关联到当前序列，确认自动监听不改名；从“扫描遗漏”打开预览后才允许人工确认处理。
- [ ] 在“扫描遗漏”预览期间关闭/卸载面板，确认批处理取消且没有文件被改名。
- [ ] 批处理第一条正在改名时关闭面板，确认当前条完整结束、后续条目不再执行。
- [ ] 关闭并重载插件后继续录音，仍生成新的 ID，不依赖或恢复任何计数器。
- [ ] 同一秒连续结束两次录音，仍生成两个不同 ID。
- [ ] 连续录音期间不需要重启面板或 Premiere；每条录音完成后磁盘名、ProjectItem 名称和媒体路径一致。
- [ ] 预先创建一个将要生成的目标名，插件重新生成 ID 并成功处理，原有 WAV 内容、大小和路径均不变；任何冲突都不覆盖文件。
- [ ] 将同一个 ProjectItem 放到两个音轨，只改名和重链接一次，不报多轨错误。
- [ ] 让同一路径关联两个不同 ProjectItem，自动监听明确跳过并记录冲突；移除重复 ProjectItem 后无需重启，下一轮自动重试并完成改名、重链接。
- [ ] 在监听启动前放入三种旧格式：无时间序号 `项目名-000019.wav`、旧项目格式 `项目名-000014-yyyyMMdd-HHmmss.wav`、旧轨道格式 `项目名-A02-021-yyyyMMdd-HHmmss.wav`；自动监听不改名。另从“扫描遗漏”打开预览，确认后才可将选中的旧格式升级为 UUID。
- [ ] schema 4 sidecar 只包含录音目录、自动启动等设置和有限条最近历史；不包含 recording counter，也不因缺少 sidecar 而阻止生成 UUID。
- [ ] 将项目文件改名或在 Premiere 中修改项目名后重载插件，已有 `旧项目名-<32位UUID>.wav` 仍被识别为已管理文件，不被二次改名，媒体路径保持在线。
- [ ] 切换序列时旧素材只进入基线；切换项目时旧监听停止。
- [ ] 隐藏面板或销毁面板后确认监听、计时器和事件解绑；隐藏期间产生的录音重新打开面板后可用“扫描遗漏”恢复。
- [ ] 连续刷新并快速切换项目时，较慢的旧请求不会把项目名、目录状态或序列覆盖回来。
- [ ] 监听中删除或断开录音目录时，监听自动停止、准备区标记目录失效，并且不会每 1.2 秒重复报错。
- [ ] 临时让目标目录只读或锁住 WAV，确认有限重试、错误日志和源文件保留。
- [ ] 模拟磁盘改名或媒体重链接失败，确认源文件名、媒体路径和素材名按文件事务回滚，sidecar 不写入成功记录。
- [ ] 让新 WAV 延迟超过 60 秒才出现在当前序列，确认警告后仍能自动处理。
- [ ] 录制一条较长音频，确认写入期间不会提前改名，停止后文件稳定才处理。
- [ ] 在“扫描遗漏”预览停留期间替换源 WAV，确认该条中止且不会重链接替换后的文件。
- [ ] 自动监听确认文件稳定后、事务开始前替换源 WAV，确认该条中止且不会重链接替换后的文件。
- [ ] 静态检查生产 `main.js` 每条录音处理路径不包含 `project.save()` 调用；连续处理多条录音期间 Premiere 不因插件触发整工程保存。
- [ ] 让 Premiere 再次生成与上一条相同的默认源文件名，确认旧源路径已从监听基线释放，新 WAV 仍会得到新的唯一 ID。

## 多人交接与离线副本

- [ ] 从同一已保存工程制作两个离线副本，由两名操作者分别在无联网、无共享计数器的环境中并行录音；两边生成的规范 WAV 名称均符合 UUID 格式。
- [ ] 将两份副本的录音合并到同一个目标目录并重新链接工程；不同录音的 32 位 ID 无重复，项目旁 sidecar 不需要手工合并计数。
- [ ] 用旧版计数命名插件产生一条 `项目名-000001.wav` 或带时间的旧格式；新版自动监听不直接改名，使用“扫描遗漏”预览确认后再升级为 UUID，并同步媒体路径和素材名；启动前已有的历史基线不应自动改名。
- [ ] 交接合并预检：同 UUID 且内容相同只保留一份；同 UUID 且内容不同不得覆盖，必须隔离并为其中一份重新生成 UUID，再只更新对应工程引用。
- [ ] 明确记录：离线 UUID 是极低概率碰撞，不是数学绝对保证；若项目要求绝对零碰撞，必须在团队流程中启用共享登记或集中分配命名空间。
- [ ] 在测试中批量生成至少 `10000` 个 UUID 并统计完整 ID，确认无重复、均为小写十六进制 32 字符；记录 Premiere/UXP 版本和随机源实现。该结果是验收证据，不是绝对数学保证。
- [ ] 注入或安排安全随机源返回一个已存在 ID，确认插件检测本地目标后重新生成并继续处理；旧目标文件从未被覆盖，冲突重试次数和最终 ID 写入活动记录。
- [ ] 在两份副本同时写入同一录音目录的压力测试中，确认目标冲突、文件锁和重命名失败都保留源文件或回滚，不损坏已存在音频；该场景需实机确认文件系统和 UXP 行为。

## 响应与连续工作

- [ ] 连续录制 `1`、`4`、`8`、`16` 条短音频，确认不需要重启面板或 Premiere，且没有录音中断或明显界面卡死。
- [ ] 连续处理 `16` 条录音后手动执行一次 `Ctrl+S`，关闭并重开工程，确认所有媒体路径和素材名一次性持久化。
- [ ] 在包含至少 1000 个 WAV 的测试目录监听 5 分钟，确认空闲轮询不会持续遍历时间线或造成明显卡顿。
- [ ] 关闭并重新打开面板后用“扫描遗漏”恢复期间产生的录音。

## 保存边界

- [ ] 在处理多条录音后使用 Premiere 自动保存或关闭项目保存提示，确认重开工程后媒体仍在线可播放。
- [ ] 记录未正常保存前崩溃/强制退出的已知风险：磁盘文件可能已改名而工程快照仍引用旧路径；重开后按“扫描遗漏”或重新链接恢复，不把该场景误判为插件已自动保存。
